# سند طراحی و ساختار سایت — منجی گیمز (Monji Games)

> این سند بر اساس ۹ تصویر مرجع و متن کامل کارفرما (گفتگوی طراحی) تهیه شده. هدف این نیست که تصاویر عیناً به UI تبدیل شوند؛ هدف استخراج **سیستم طراحی، معماری اطلاعات و محتوا** از دل آن‌ها و تبدیلش به یک ساختار ریسپانسیو و قانون‌مند است که هم برای توسعه‌ی مستقیم و هم برای دادن به یک ابزار هوش مصنوعی توسعه‌دهنده قابل استفاده باشد.

---

## ۰. خلاصه تصمیمات کلیدی

| موضوع | تصمیم |
|---|---|
| زبان | دوزبانه: فارسی (RTL، پیش‌فرض) + انگلیسی (LTR) |
| بک‌اند | واقعی — محتوای مهم از گوگل‌شیت خوانده می‌شود؛ فرم ثبت‌نام در گوگل‌شیت دیگری ذخیره می‌شود |
| خروجی این سند | فایل ساختاریافته (این فایل) برای مصرف مستقیم توسط تیم توسعه / ابزار AI |
| فونت | تنوع بالا اما کنترل‌شده (سیستم نقش‌محور، نه آشوب بصری) |
| منبع حقیقت طراحی | متن نهایی کارفرما اولویت دارد؛ تصاویر = مرجع حس‌وحال بصری، نه پیکسل‌به‌پیکسل |

## ۱. اصول پایه طراحی

### ۱.۱ قانون طلایی هر سکشن
هر سکشن، **فقط یک پیام اصلی** منتقل می‌کند. اگر سکشنی هم‌زمان چند ایده دارد، یا تقسیم می‌شود یا محتوای اضافه حذف می‌شود. این قانون در بازبینی هر صفحه باید چک شود.

### ۱.۲ نسبت بصری
- ۶۰٪ فضای خالی و محتوای متنی
- ۳۰٪ تصویر سینمایی / گرافیک بازی
- ۱۰٪ تزئینات تاریخی (خطوط، بافت، هندسه‌ی ایرانی-اسلامی در حد ظریف — نه غالب)

### ۱.۳ سبک کلی
واقع‌گرایانه، تاریخی، سینمایی، مدرن. نه UI فانتزی پرزرق‌وبرق، نه سایت شرکتی خشک. تیره اما نه مثل غار — یعنی کنتراست و نور کافی برای خوانایی.

## ۲. سیستم طراحی (Design System)

### ۲.۱ پالت رنگی

| نقش | رنگ | پیشنهاد HEX | توضیح |
|---|---|---|---|
| پس‌زمینه اصلی | سبز یشمی خیلی تیره | `#0B1F1A` | زمینه‌ی غالب صفحات |
| سطح دوم (کارت‌ها، پنل‌ها) | سبز یشمی، کمی روشن‌تر | `#122A24` | تمایز لایه از بک‌گراند اصلی |
| تاکید / CTA / خطوط / آیکون | مسی | `#C17A4C` | دکمه‌ها، خطوط جداکننده، آیکون فعال |
| تاکید Hover/فعال | مسی روشن‌تر | `#DA9762` | حالت Hover و تب فعال |
| تیتر و متن مهم | بژ صحرا | `#E8D9B3` | H1 تا H4، لیبل‌های کلیدی |
| متن ثانویه / خنثی | خاکستری فولادی | `#8C97A0` | پاراگراف‌ها، توضیحات کوتاه |
| عمیق‌ترین لایه (سایه/اورلی) | مشکی محدود | `#05100D` | فقط برای گرادیان زیر Hero یا Overlay روی تصویر، هرگز به‌عنوان بک‌گراند اصلی |

قانون: مشکی خالص هیچ‌وقت به‌عنوان رنگ سطح استفاده نمی‌شود؛ فقط در گرادیان‌های محو برای خوانایی متن روی تصویر.

### ۲.۲ سیستم تایپوگرافی (چندفونتی کنترل‌شده)

چون درخواست تنوع فونت بالا بود، به‌جای یک فونت برای همه‌چیز، **نقش‌ها را از هم جدا می‌کنیم** تا تنوع باعث شلوغی نشود:

| نقش | فونت پیشنهادی (فارسی) | فونت پیشنهادی (انگلیسی) | مورد استفاده |
|---|---|---|---|
| تیتر نمایشی / Hero | Lalezar یا Morabba ExtraBold | Cinzel | H1 صفحات، عنوان Hero |
| تیتر بخش‌ها | Vazirmatn Bold/Black | Cinzel یا Cormorant SemiBold | H2/H3 |
| بدنه متن / UI | Vazirmatn Regular/Medium | Inter یا Source Sans 3 | پاراگراف، دکمه، منو |
| نقل‌قول‌ها و شعارها (مثل «ملتی که در برابر هجوم بیگانگان...») | فونتی با حس خوشنویسی/کتیبه (مثل Homa) | Cormorant Italic | جمله‌های تزئینی پایین صفحات |
| اعداد و آمار (درصدها، منابع) | Vazirmatn با وزن سنگین + Tabular Numbers | همان | شمارنده‌ها، درصد پیشرفت، مقادیر منابع |

این‌ها پیشنهاد اولیه‌اند و باید در استودیوی طراحی روی نمونه واقعی تست شوند؛ اصل مهم این است که **حداکثر ۲ فونت در هر صفحه هم‌زمان دیده شود** (یکی تیتر، یکی بدنه) حتی اگر کتابخانه‌ی کلی سایت ۵ فونت داشته باشد.

### ۲.۳ فاصله‌گذاری و گرید
- گرید ۱۲ ستونه برای دسکتاپ، ۴ ستونه برای موبایل
- فاصله‌ی سخاوتمندانه بین سکشن‌ها (حداقل ۹۶ پیکسل دسکتاپ / ۴۸ پیکسل موبایل) — این فضای خالی بخشی از هویت بصری است، نه کمبود محتوا
- عرض حداکثر محتوا (Max-width) حدود ۱۲۸۰ تا ۱۴۴۰ پیکسل، خارج از آن فقط تصویر پس‌زمینه کشیده می‌شود

### ۲.۴ تزئینات و آیکون‌ها
- تزئینات ایرانی-اسلامی فقط در: گوشه‌ی قاب‌ها، بافت بسیار کم‌رنگ پس‌زمینه، خط جداکننده‌ی سکشن‌ها
- آیکون‌ها Line-style با رنگ مسی، نه Flat رنگی پر

### ۲.۵ رفتار تصاویر
- تصاویر سینمایی (Hero و پس‌زمینه‌ها) با Overlay گرادیانی تیره از پایین/کنار برای خوانایی متن روی آن‌ها
- روی موبایل، تصاویر عریض که کنار متن قرار دارند به بالای متن منتقل می‌شوند (نه کنار هم)

## ۴. هدر و فوتر سراسری

**نکته مهم:** در تصاویر مرجع دو نسخه‌ی متفاوت از منوی هدر دیده می‌شود (یکی با «تماس با ما / رسانه / اعضای حکومت‌ها»، دیگری با «صالح / معرفی بازی») که هیچ‌کدام دقیقاً با ساختار نهایی متن کارفرما یکی نیست. **منبع حقیقت، متن نهایی است**، نه تصاویر (که ظاهراً پیش‌نویس‌های قبلی بوده‌اند).

### هدر (بر اساس متن نهایی)
- آیتم‌های منو: `خانه | شهر | منابع | ارتش و نبرد | جهان بازی | روند توسعه | اخبار | تیم`
- لوگوی Monji Games گوشه‌ی راست (چون فارسی RTL است)
- CTA مسی سمت چپ: «دنبال‌کردن پروژه»
- سوییچر زبان (FA/EN) کنار CTA
- رفتار: ارتفاع کم، تقریباً شفاف روی Hero صفحه خانه؛ بعد از اسکرول به سبز یشمی تیره‌ی Solid تبدیل می‌شود (Sticky)
- موبایل: منو به همبرگری تبدیل می‌شود؛ CTA و سوییچر زبان در بالای منوی باز شده باقی می‌مانند

### فوتر
(در متن مرجع مشخص نشده — پیشنهاد استاندارد، قابل تأیید کارفرما)
- لوگو + یک جمله کوتاه معرفی
- لینک سریع به ۸ صفحه
- آیکون شبکه‌های اجتماعی
- کپی‌رایت + شعار پایانی (مشابه الگوی «ساخته‌شده برای آینده‌ای بهتر» که در تصویر ۸ دیده می‌شود)

## ۶. مشخصات هر صفحه

> محتوای فارسی زیر عیناً از متن کارفرما گرفته شده. برای نسخه‌ی انگلیسی، باید توسط تیم ترجمه/بازنویسی شود (نه ترجمه‌ی ماشینی مستقیم، چون لحن سینمایی حفظ باید شود).

### ۶.۱ خانه
1. **Hero** (تقریباً تمام‌عرض): سمت راست تیتر «حکومت تاریخی خودت رو بساز؛ تصمیم‌هات مسیر تاریخ رو عوض می‌کنه» + زیرتیتر توضیحی + دو CTA («کشف دنیای بازی» → صفحه جهان بازی، «روند توسعه» → صفحه روند توسعه). سمت چپ آرتورک سینمایی فرمانروا+شهر+ارتش.
2. **۴ کارت باریک** بدون توضیح اضافه: شهر و ساختمان‌ها / منابع و اقتصاد / ارتش و نبرد / جهان و تعامل — هرکدام یک جمله کوتاه.
3. **سکشن آرام** با تیتر «یک پروژه بزرگ، ساخته‌شده در ایران‌زمین» + نقل‌قول کوتاه درباره‌ی منجی گیمز + نوار Progress کوچک (از داده‌ی زنده‌ی گوگل‌شیت).

### ۶.۲ شهر و ساختمان‌ها
- تصویر بزرگ شهر بالای صفحه
- ۴ تب دسته: حکومتی / نظامی / اقتصادی / دفاعی و پشتیبانی
- با کلیک روی هر تب، فقط ساختمان‌های همان دسته (کارت: تصویر+نام+یک‌جمله) نمایش داده می‌شود
- نمونه محتوا: مسجد «برای به‌دست‌آوردن قهرمان‌های نظامی»، شفاخانه «درمان سربازان زخمی پس از نبرد»، پادگان «محل آموزش نیروهای حکومت»
- پایین صفحه: مقایسه تصویری سطح۱ → سطح بالاتر (نه توضیح متنی زیاد)

### ۶.۳ منابع و اقتصاد
- ۶ کارت منبع در چیدمان ۳×۲: گندم، چوب، سنگ، آهن، نقره، یاقوت — هرکدام آیکون+نام+یک‌جمله
- سکشن شاخص «ارتشت هزینه دارد» با توضیح کوتاه ارتباط اقتصاد و قدرت نظامی
- **حذف شده طبق دستور کارفرما:** بخش «انبار بی‌نهایت نیست»

### ۶.۴ ارتش و نبرد
- Artwork سینمایی میدان نبرد بالا + تیتر «ارتش بزرگ کافی نیست؛ ترکیب درست مهم‌تر است.»
- ۴ کارت نیرو: پیاده‌نظام، کماندار، سواره‌نظام، منجنیق
- **چرخه برتری نیروها**: دیاگرام دایره‌ای پیاده‌نظام → کماندار → سواره‌نظام → پیاده‌نظام، هرکدام با برچسب «×۱.۵ قدرت مؤثر»
- منجنیق جدا از چرخه معرفی می‌شود (نقش تخصصی)
- دو کارت پایانی: «لشکرکشی» و «دفاع»
- **حذف شده:** بخش «نبرد و غارت»

### ۶.۵ جهان بازی
- فعلاً بدون اسکرین‌شات واقعی نقشه → Artwork سینمایی اختصاصی (نمای وسیع سرزمین، چند حکومت، جاده، شهر، فورت)
- ۳ کارت: بازار و تجارت / اتحاد / فورت‌ها
- **حذف شده:** کارت «لشکرکشی» از این صفحه (چون در صفحه ارتش و نبرد هست)
- یادداشت فنی: وقتی نقشه واقعی بازی طراحی شد، Hero حفظ می‌شود و اسکرین‌شات واقعی پایین صفحه اضافه می‌شود

### ۶.۶ روند توسعه
- وسط صفحه: حلقه Progress بزرگ با عدد درصد کلی (مثلاً ۶۸٪) — **این عدد از پنل مدیریت/گوگل‌شیت خوانده می‌شود، نه هاردکد**
- ۷ ردیف باریک مینیمال زیر آن: هسته و زیرساخت / شهر و ساختمان‌ها / منابع و اقتصاد / ارتش و نبرد / جهان و تعاملات / UI و گرافیک / تست و بهینه‌سازی — هرکدام: اسم راست، نوار وسط، درصد چپ. همه از داده‌ی زنده.
- ۳ کارت پایانی: تمرکز فعلی / آخرین تغییر / قدم بعدی (این‌ها هم از گوگل‌شیت قابل ویرایش)
- این صفحه باید بسیار خلوت بماند

### ۶.۷ تیم
- تیتر: «یک تیم حرفه‌ای، پیگیر و بااراده پشت این پروژه است.» — بدون پاراگراف معرفی اضافه
- چیدمان ۹ نفر: ۵ نفر ردیف اول + ۴ نفر ردیف دوم (نه ۳×۳)
- هر نفر: Portrait سیاه/سیلوئت با نور لبه مسی + نام + نقش
- اعضا: سرکار خانم دیده‌بان (کدنویس فعال)، سرکار خانم هیناتا (کدنویس فعال)، آرشام زند (ایده‌پرداز، مدیر توسعه پروژه)، محمدحسین نصیری (مدیر فنی پروژه)، نیما شهسوارزاده (کدنویس فعال)، امیرعلی خدادادپور (کدنویس و گیم‌دیزاینر)، سید مهدی سجادی (کدنویس)، مجتبی بیک‌پور (کدنویس)، فاضل علیزاده (کدنویس)
- این لیست هم پیشنهاد می‌شود از گوگل‌شیت خوانده شود تا تغییر عضو نیاز به دیپلوی مجدد نداشته باشد

### ۶.۸ اخبار و Devlog
- تیتر: «منجی چطور ساخته می‌شود؟»
- جدیدترین Devlog: Thumbnail بزرگ (~۶۰٪ عرض) با دکمه Play وسط + عنوان/تاریخ/۲خط توضیح کنارش
- ۳ Devlog قبلی با Thumbnail متوسط
- فیلتر ساده: همه | توسعه | گرافیک | گیم‌پلی | فنی
- وقتی ویدیو پخش می‌شود، بقیه رابط کاربری باید محو/کم‌رنگ شود تا تمرکز کامل روی محتوا باشد
- **باز:** میزبانی ویدیو (یوتیوب Embed یا سلف‌هاست) هنوز مشخص نیست — نیازمند تأیید کارفرما (بخش ۱۱)

## ۷. معماری داده و بک‌اند (گوگل‌شیت)

طبق درخواست، محتوای مهم و قابل‌تغییر باید از یک گوگل‌شیت خوانده شود، و فرم ثبت‌نام باید در گوگل‌شیت دیگری ذخیره شود. پیشنهاد ساختار:

### ۷.۱ شیت «محتوای سایت» (فقط‌خواندنی برای سایت)

**تب `Progress`**

| ستون | توضیح |
|---|---|
| `OverallPercent` | درصد کلی پیشرفت (برای حلقه اصلی) |
| `SectionName_FA` / `SectionName_EN` | نام هرکدام از ۷ بخش |
| `SectionPercent` | درصد آن بخش |
| `CurrentFocus_FA/EN` | متن کارت «تمرکز فعلی» |
| `LastChange_FA/EN` | متن کارت «آخرین تغییر» |
| `NextStep_FA/EN` | متن کارت «قدم بعدی» |

**تب `Team`**

| ستون | توضیح |
|---|---|
| `Order` | ترتیب نمایش (برای چیدمان ۵+۴) |
| `Name` | نام عضو |

### ۷.۳ روش فنی پیشنهادی اتصال

چون سطح فنی پروژه هنوز بین «پلتفرم آماده» و «کد اختصاصی» مشخص نشده، راهکار زیر با **هر دو** سازگار است:

- ساخت یک **Google Apps Script Web App** که هم‌زمان:
  - با متد `GET` محتوای شیت `محتوای سایت` را به‌صورت JSON برمی‌گرداند (برای خواندن در فرانت)
  - با متد `POST` داده‌ی فرم ثبت‌نام را در شیت دوم می‌نویسد
- این روش نیاز به سرور اختصاصی ندارد، با فرانت React/Next، HTML خام، یا حتی یک قالب وردپرس (از طریق fetch/AJAX) کار می‌کند
- جایگزین: استفاده مستقیم از Google Sheets API با کلید API محدود (Read-only) برای محتوا، و یک فرم‌هندلر ساده (مثل Apps Script یا سرویس‌هایی مانند SheetDB) برای نوشتن ثبت‌نام

## ۸. دوزبانگی (فارسی/انگلیسی)

- فارسی زبان پیش‌فرض و RTL؛ انگلیسی LTR
- ساختار URL پیشنهادی: صفحات فارسی بدون پیشوند (`/`, `/army`)، صفحات انگلیسی با پیشوند `/en/` (`/en`, `/en/army`)
- تمام متن‌های ثابت (کارت‌ها، تیترها) باید در دو نسخه‌ی FA/EN در کد یا فایل ترجمه نگه‌داری شوند
- محتوای دینامیک (گوگل‌شیت) هم باید ستون `_FA` و `_EN` جدا داشته باشد (طبق جدول بخش ۷)
- جهت (`dir="rtl"`/`dir="ltr"`) باید در سطح `<html>` بر اساس زبان انتخاب‌شده تغییر کند؛ کل گرید و آیکون‌های جهت‌دار (فلش، chevron) باید آینه شوند

## ۱۱. فرض‌ها و سؤالات باز برای تأیید کارفرما
